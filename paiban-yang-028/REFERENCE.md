## 二、输入适配器（T1）

| 输入 | 取法 | 注意 |
|---|---|---|
| 静态网页 URL | `WebFetch`（要正文，不要导航） | 抓回即写入 `原文.txt`；来源 URL 记 `来源.md` |
| SPA / 需登录 / 反爬 | browser-use：`navigate_page` → `take_snapshot`，取文本节点 | 拿不全就说拿不全，不用记忆补内容 |
| PDF（有文本层） | Read 工具直读；长文件分段读（单次 ≤20 页） | 分段边界处易丢字 → 合并后与页码字数对账 |
| PDF（扫描件） | **本机无 OCR 内置** → 标〔不可排〕，交帆决定是否走 OCR 专项 | 不要凭图猜字 |
| md / txt | Read 直读 | md 的语法符号（# - |）属呈现物，取语义文字入基准 |
| html | Read 或 `python -c` 去标签取文本 | 去标签后的字符集才是 `原文.txt`，别把标签当内容 |
| .py 及代码 | Read 直读，**只换呈现** | 缩进即语法：统一显示宽度、加分层空行，**绝不回写源文件** |
| 音频（m4a/mp3/wav） | `py -3.12 scripts/asr.py --audio a.m4a b.mp3 …`（可多份、可给目录、可通配） | 见下节 |
| epub / azw3 / mobi | `py scripts/epub2md.py --in book.epub --out 源文档.md`（背后调 pandoc `-f epub -t gfm --extract-media=media`） | DRM、加密或解析失败 → 标〔不可排〕；内嵌字体/样式丢弃，只取内容与图 |
| 百度网盘分享 | 先拿分享链接里的真实文件（txt/pdf/epub）到本地，再按对应类型走 T1 | 不要在线预览；预览页是重排版过的 HTML，会丢字/改字 |
| GitHub URL | 单文件：Read 直读 raw；仓库/目录：只取本次要排的那一个文件，不整仓克隆 | 不要把 README 的渲染页当源文件，代码块里的 `<>` 会触发 HTML 标签问题 |
| 微信群 / 知识星球 txt | 先走「噪声剥离流程」（见下），再写 `原始粘贴.txt` 并对账 | 群聊件里含昵称、时间戳、转发链、半截引用，直接排会污染原文 |
| 图片 | T1 把图落盘 `images/` 并改纯英文名；网络图先下载、失败占位并报数；落盘后走 T1b 图片子流程（诊断分流 → 台账 → 重绘件帆确认） | typeset 不联网，遇 URL 直接抛错；分流与重绘细则见「图片处理（T1b）」节 |
| 截图（.png 附件） | 帆直接发截图进对话：从会话 attachments 目录拷进任务目录 `images/img_NNN.png`，走「图片处理（T1b）」同一套分流 | 表格/代码截图 → 重绘；照片/插图 → 照搬；**整页文字截图 → `imgredraw.py --kind text`**，产物剥注释头后进散文管道，按 ASR 同款容错纪律纠字 |

### T1 对账（必做，v0.6 新增）

机检第 1 项比的是 `原文.txt` ↔ 成品 HTML，**两边同出一源**：T1 阶段就丢了字，八项会全绿着把错字送出去。
所以 `原文.txt` 写定后立刻对账一次，粘贴件还要留 `原始粘贴.txt` 作底稿：

```
py -3.12 scripts/t1_audit.py --src 源文档.md --orig 原文.txt --md      # md 语法符走 B 档，只报告
py -3.12 scripts/t1_audit.py --src 原始粘贴.txt --orig 原文.txt        # 粘贴/转写件：直接比
```

A 档差异（丢/多里有汉字、字母、数字或 `_ . / :`）= 改过字，回 T1 修，不进 T3。
2026-09-21 实测：一份技术文档的 `KIMI_CODE_HOME` 被 md 强调符规则吃掉 27 个下划线，八项机检一项没报。

### 群聊 / 知识星球 txt 噪声剥离流程

群聊件、星球贴不是文章：一条消息一行，夹昵称、时间戳、引用链、系统提示、重复转发。T1 必须先清再排，否则版式会忠实还原噪声。

流程：

1. **存底稿**：原文件原样写入 `原始粘贴.txt`（T1 对账基准）。
2. **剥元信息**：删除行首 `昵称 时间`、`[引用]`、`—— 转发`、`@某人`、系统提示行（如「已邀请…」「消息已发出但被对方拒收」）。
3. **还原转发**：把「转发自 xxx：」后的正文提到本行；保留被引用原文时，用 `>` 标出来源，不混进正文。
4. **去重复与半截引用**：连续重复的消息只留一条；被抠断的句子用 `（待核）` 标缺口，不猜字。
5. **聚合同一发言人**：同一人在短时间内的连续消息合并成段落，段落间用空行分隔。
6. **对账**：清完的文本与 `原始粘贴.txt` 跑 `t1_audit.py`；A 档差异必须只在「剥掉的元信息」上，正文不许丢字改字。

禁止：把「剥噪声」当成「改写内容」——删正文句子、调语序、补过渡句都归 rbook / lbook 管。

### 音频适配器（asr.py）实测事实

- 环境：**必须 `py -3.12`**（默认 3.14 无 wheel）；不需要 ffmpeg（PyAV 自带解码）。
- 模型：faster-whisper **small**（486MB，已在本地缓存）；下载走 `HF_ENDPOINT=https://hf-mirror.com`，实测 6.4 MB/s；huggingface.co 直连不通。
- **后端：GPU 已通**（cuda/float16）。前提=装 `nvidia-cublas-cu12` + `nvidia-cuda-runtime-cu12` + `nvidia-cuda-nvrtc-cu12`（pip 即可，约 1GB 磁盘）；脚本启动时自动把这些 wheel 的 `bin` 挂进 DLL 搜索路径。
  - **坑（已修）**：`os.add_dll_directory()` 的句柄必须常驻保存——句柄被回收后搜索目录立刻失效，报的仍是 `cublas64_12.dll not found`。
- 速度（2026-09-19 实测，RTX 4060 Laptop）：

| 后端 | 实时率 | 1 分钟音频 | 1 小时音频 |
|---|---|---|---|
| CPU int8 | 2.96x | 约 20 秒 | 约 20 分钟 |
| **GPU float16** | **12.5–15x** | 约 4.5 秒 | **约 4–5 分钟** |

- 准确率（同一段 65.5 秒中文音频、逐字比对真值）：CPU int8 **CER 8.0%** → GPU float16 **CER 3.6%**（251 字基准，错 9 字）。错误类型仍全为同音字替换（利→立、稿→搞、册→侧）。
- 批量：多份共用一次模型加载（首份含约 6 秒预热，之后每份约 4.5 秒/分钟音频）；输出 `<名>.转写.txt` + `<名>.segments.json`。
- 长录音（>30 分钟）走后台跑，别占住对话。
- **真人语音实测**（2026-09-19，李笑来写作课 9 份、6.6 小时）：可懂度够，但错得比合成稿密——**专名与术语是重灾区**（「李笑来」六种错法、「副词」全课被听成「复词」43 次、「作者」被听成「坐着」），成语类错密集（一蹴而就/慷他人之慨/拗口/由衷）。无真值可比，故**不给 CER 数字**，只给结论：**长课必须配「词表 + 待核清单」双闸**，否则读者无从知道哪句是听错的。
- 处置纪律：转写文本进 T2 前先按语义纠同音字（复用 prompt-yang-014 语音容错条款），拿不准标〔待确认〕，不猜字。
- **反复读参数（必开）**：`condition_on_previous_text=False` + `no_repeat_ngram_size=4` + `repetition_penalty=1.15` + `compression_ratio_threshold=2.2`。实测第01课未开时「复词呢」连八遍、「这只是一个误会」连六遍；开了之后最高频五字组 24 次→9 次，总字数 9090→8443（少掉的全是幻觉），速度不掉。
- **纠字只做有据可查的替换**：词表用 json（`{"错写":"正写"}`），每条键必须在语料里真出现过才收录（见 `建纠字表` 的做法）。短语做键避免误伤（`有时间经历`→`有时间精力`，而不是 `经历`→`精力`）。
- **引语 ≠ 标注**：原文自带的整段「」（含句末标点）不受 ≤12 字与密度纪律约束；check.py 的 `annotations()` 已按此过滤。

### 图片处理（T1b）

知识性图片（表格 / 代码截图 / 架构图 / 整页文字截图）照搬进 PDF 会糊、字小看不清。T1b 的做法：**诊断分流先行，重绘走人工闸**——OCR 产物机器验不了对错，与 ASR 同一条「不猜字」纪律。

OCR 引擎 = **RapidOCR**（onnxruntime 底座，numpy 2 原生；首跑自动下载自带模型约 40MB）。PaddleOCR 老路已废弃勿重试（2026-09-30 实测：paddleocr 3.x 删了 PPStructure；paddle 2.6 栈在本机 oneDNN/`scale` op 报错，全部 FLAGS 无效）。

**分流规则**（`py -3.12 scripts/imgdiag.py --task 任务目录`，逐张落 `图片台账.json`）：

| 类别 class | 判据 | 建议动作 action（proposed，待帆拍板） |
|---|---|---|
| as-is | 等效 DPI ≥150 且文字占比低（清晰插图/照片） | 照搬，现有管道不动 |
| table | 横竖线网格结构（≥3横+≥2竖 或 ≥2横+≥3竖；纯像素判，不需要 OCR） | `redraw-table`：imgredraw 重绘为 md 表格 |
| code | OCR 到 ≥4 行且代码特征字符多（= ; { } ( ) 等） | `redraw-code`：imgredraw 重绘为代码块 |
| diagram | 文字占比中低、非表格线结构（架构图） | 本期照搬+警告；Mermaid 重绘在 P2，只登记命令 |
| review | 疑似知识图（宽 ≥400px 且等效 DPI <150）但无 OCR 细分不了 | 人工判型，或装 OCR 重跑 imgdiag |

等效 DPI 口径与 typeset 同源：`纸面宽 = min(px_w/120×25.4, 160mm)`，`等效 DPI = px_w/纸面宽`（<150 判「打印会糊」）。
无 RapidOCR 也能跑：只按 尺寸 + 等效 DPI + 横竖线网格 分流，Pillow 也没有时走内置 stdlib PNG 解码兜底。
网格线的降采样是「先二值化再 min-pool」——直接均值缩放会把 1px 浅灰表格线平均掉（2026-09-30 实测：900×320 表格图缩到 600 宽后 4 条竖线全丢，误判 code）。
`--pdf 书.pdf` 模式先用 pypdfium2 把 PDF 内嵌图抽进 `images/` 再逐张诊断（覆盖「资料常是 PDF」的场景）。

**重绘**（帆看台账拍板后）：

```
py -3.12 scripts/imgredraw.py --img images/img_001.png --kind table --task 任务目录
py -3.12 scripts/imgredraw.py --img images/img_002.png --kind code  --task 任务目录
py -3.12 scripts/imgredraw.py --img images/img_003.png --kind text  --task 任务目录
```

产物落 `redraw/`：table/code → `img_NNN.md`（表格 = RapidTable 出 HTML 结构 → stdlib 转 md 表格；代码 = OCR 按 y 聚行、x 排序、x0 折算缩进）；
整页文字（text）→ `img_NNN.txt`，头部注释写明容错纪律（替换进源文档时剥掉 `#` 注释头，不进 `原文.txt`）。
随后：① AI 把产物替换进 `源文档.md`（原图片行 → md 表格/代码块/正文，走现有管道进 `原文.txt`，铁律 1 照常执法）；
② 帆人眼对原图确认，拿不准的字标〔待确认〕；③ 台账该图 `confirmed` 置 true。机检第 10 项对 `redrawn` 未确认一律判红。

**傻瓜式安装步骤**（缺库时 imgredraw 会 exit 2 并原样打印这份）：

```
py -3.12 -m pip install rapidocr rapid-table    # 一步到位（onnxruntime 底座）
py -3.12 scripts/selftest.py                    # 验证：imgredraw-ocr / imgredraw-text 项由 skip 变 OK
```

也可以不装：imgdiag 的降级分流不需要任何三方库，重绘件可人工转写后手动记台账 `action=redrawn` + 产物路径。

**独占图页**（帆拍板项）：诊断对「重绘不了又缩到看不清」的图给建议，帆点头后
`py -3.12 scripts/typeset.py --in 源文档.md --dir 任务目录 --md --fig-fullpage img_007.png`（可多次，源文件名与 img_NNN 名都认）。
该图独占一页、内容上限放宽到 200mm（页框高）、无写区；机检第 6/7 项凭 `data-figpage` 豁免 140mm（真品墨迹下限放宽到距页顶 225mm），
typeset 自动把台账登记为 `action=fullpage + confirmed=true`，第 10 项要求台账与 `data-figpage` 页互证。

**P2 登记（本期不实现）**：架构图 Mermaid 重绘；Real-ESRGAN 超分（`realesrgan-ncnn-vulkan` 或 pip `realesrgan`，届时补实测）。

## 三、hook 注册（**当前未启用**——帆 2026-09-19 定「暂不注册，先纯手动」）

`scripts/gate.py` 已就绪并通过 11 项场景测试；下面的片段是将来启用时照抄用的，**现在两处宿主配置都没有它**。启用后需重启宿主生效；逃生门 `PAIBAN_GATE=off` 或命令加 `--paiban-ok`。

闸口只能设在**渲染命令执行之前**——kimi-code 只有 UserPromptSubmit / PreToolUse / Stop / Notification 四个事件，**没有 PostToolUse**。

**Qoder**（用户级 `C:\Users\Lenovo\.qoder-cn\settings.json`，或项目级 `.qoder/settings.json`）：

```json
{
  "hooks": {
    "PreToolUse": [
      { "matcher": "Bash",
        "hooks": [ { "type": "command",
          "command": "py -3.14 C:\\Users\\Lenovo\\.qoder-cn\\skills\\paiban-yang-028\\scripts\\gate.py" } ] }
    ]
  }
}
```

**kimi-code**（`C:\Users\Lenovo\.kimi-code\config.toml`）：

```toml
[[hooks]]
event = "PreToolUse"
matcher = "Bash"
command = "py -3.14 C:\\Users\\Lenovo\\.kimi-code\\skills\\paiban-yang-028\\scripts\\gate.py"
```

**放行规则（gate.py 实际逻辑，按序）**：

1. 命令不含渲染特征（`--print-to-pdf` / `render.py` / `md2pdf` / `headless` + edge/chrome）→ exit 0 不管。
2. 命令含 `--paiban-ok` → 放行（帆明确授权直出）。
3. 环境变量 `PAIBAN_GATE=off` → 放行（调试逃生门）。
4. 从命令里解析目标 `.html`，其同目录 `机检.json` 存在且 `pass: true` → 放行。
5. 其余 → **exit 2 阻塞**，stderr 给一行理由：先跑 `/paiban` 或补 `--paiban-ok`。

**注册前自测**（不写配置就能验）：

```
echo {"tool_name":"Bash","tool_input":{"command":"edge --headless --print-to-pdf=a.pdf a.html"}} | py -3.14 scripts/gate.py ; echo exit=%errorlevel%
```

预期：无凭据时 exit=2；带 `--paiban-ok` 时 exit=0。

## 四、失败与处置

| 现象 | 根因 | 处置 |
|---|---|---|
| check.py 报 `char_conservation FAIL` | 排版时删了原文句子或改了词 | 补回原文，不许改判据；确实要删 → 交回 rbook 类做内容决定 |

## 五、Markdown 适配器（typeset.py --md）实测事实

结构映射：`#`→`h1..h3`（更深压到 h3）｜`- * +`/`1.`/`>`→`.para l1..l4`（层级只由缩进表达）｜
`|`表→`<table>`（跨页时首块留表头、续块 `class="cont"` 加重顶线，**不重复表头**——重复就是加字，违铁律 1）｜
三反引号→`.code-block`｜`---`/`***`→`<hr class="sep">`（同级硬断，`-` 不进规范化序列，所以渲成 hr 不违铁律 1）。

去语法但**不丢字**：`[文](链)` → `文（链）`（URL 是内容，删了就少字）；`** * ~` 是标点级强调符，可去。
**下划线例外**：只在词边界上才当强调符剥（CommonMark 同一条规则），代码段与非代码段分开处理——
`KIMI_CODE_HOME`、`auto_install` 里的 `_` 是标识符的一部分，剥了就是改字（v0.6）。
`原文.txt` 由**渲染用的同一批块**反推（`blocks_source_text`），不许先摊平再解析——那样 `#`/`|`/三反引号 已经没了，整篇会退化成一段。

`--keep-base` 在 md 模式**直接拒**（原因同上）。要人工改字：改源 `.md`，或走 `--fix` 词表。

标注注入默认**不开**：技术文档自带密集符号，再加一层只会顶破密度 ≤3；需要时传 `--marks 标注词表.json`，注入的条目会落进 `标注清单.json` 供机检执法。

**图块（引擎自带，`--md` 模式）**：独立成行的 `![alt](路径)` → `('img', src, alt[, 题注])`，
再由 `_normalize_img` 把图拷进任务目录 `images/img_NNN.ext`（纯英文名，避开中文路径编码坑）、
同图去重、读出真实像素写进块。五条要紧的：

① **路径不进 `原文.txt`**（进了就是加字）。进基准的只有 alt 与题注，按源序：图片行的 alt 在前，
紧跟其下的「图3-1 …」题注在后。图注**只印原文**，版式不自带「（图：）」这类壳——
铁律 1 是严格守恒，加一个字就判红。
② **题注并进同一块**，判据 `^(?:图|表)\s*\d+[-–]\d+\s`。编号后那个空格不能省：
正文里「图3-5展示了……」这类句子会被当题注吞进图块（实测图块量到 202.8mm，硬半页失守）。
不分块的收益：图与注分成两块时，实测差 0.5mm 就把注挤到下一页开头，纸面变成「整页一张图 + 题注孤零零」。
③ **图注走正文同一套切行**（≤36 字 / ≤37.8em / 禁则），只是居中排、降到注释字号（9.6pt）。
直出整串会印成一整行超长字，机检第 5 项判红。
④ **尺寸闸在生成端**：宽 ≤160mm（版心物理边界），高 = 当前 `cap` − 块距 10mm −（有图注再扣 10mm）
− 拆块预留量，等比缩放后把 mm 显式写进 `style`。闭环每收紧一次 `cap` 就重算尺寸、重量一次高度；
超高**只缩不拆**（拆了就不是图），预留堆到 `cap − 48mm` 下限仍装不下，就交机检判红让人来看。
⑤ **量高与渲染都要看得见图**：`measure()` 在任务目录下建 `.paiban_measure/`（相对 `images/…` 才可解析），
`render.py` 把渲染副本里的 `<img src>` 改写成绝对 file URI、原件保持相对路径。
两条各治一半：只改 render 的话量高时图按 0 高记账，硬半页对含图页失效；只留相对路径的话纸上印出裂图。
配套机检：第 6 项顶层块清单含 `<figure>`（漏了它 `data-mm` 条数对不上 → 含图页悄悄退回估算，
而估算模型里没有图高）；第 7 项把**图片矩形墨迹**算进真品边界（只量字的话「图压进写区」这道闸对图全部失明，
本机 PDF 库若读不到图像对象，detail 会明说「图的墨迹未纳入」）；第 9 项 `img_integrity` 查图源是否存在。
回归执法：`selftest.py` 的 `caption-merge` / `fig-page-measured` / `md+image` / `missing-image` 四项。

| 91 个 .page 印成 96 张、5 张全白 | 框高 216mm 距可印区 222mm 只差 6mm，Edge 个别页尾仍多断一次 | A/B 实测：200mm → 91 张 0 白。断页属性写法（break-after / page-break-after 单留任一）无效，别往那条路上查 |

| 第 8 项 printed_text | `.page` 一旦裁切，第 7 项量不到被裁掉的墨点 | 从成品 PDF 抠字与 原文.txt 逐字比；收紧版式不许变成悄悄丢字 |
| 图上纸是裂图（破图图标） | render.py 把 html 拷进英文临时目录渲染，相对 `images/…` 在临时目录解析不到 | 渲染副本里把 `<img src>` 改写为绝对 file URI（2026-09-26 实测抓到）；原件保持相对路径，排版.html 可随 images/ 整体搬移 |

## 六、长件适配

长件模式处理整本书/超长博客/多份转写，由 `scripts/longdoc.py` 提供机械臂，AI 负责 L0-L5 编排。

### 切章规则

- **md 模式**：先按 h1 切；章 > `--max-chars`（默认 20000）则在该章内按 h2 再切；仍超则按 h3 切。
- **散文模式**：按段落边界在 max-chars 附近切，落刀必须在句末标点（。！？）之后，不腰斩句子。
- **硬约束**：绝不切在代码围栏（```）内部、表格（连续 `|` 行）内部。
- **图片路径重写**：`split` 阶段把 `![alt](相对路径)` 按源 md 所在目录解析并重写为绝对路径；http(s) URL 原样保留（typeset 会对网络图报错，取图是 T1 的活）。

### 结构台账

`结构台账.json` 记录：
- `source`：源文件绝对路径；
- `totals`：对源文件的结构计数（h1/h2/h3、表格、代码块、图片等）；
- `chunks`：每章的文件名、标题、字符数、counts；
- `checksum_ok`：各章 counts 求和是否等于 totals。

`assemble` 会**对源文件重算** totals 并与各章求和再对一次账；源文件被帆改动后对不上 → 红，不合并。

### 断点续跑

- L3 逐章排检时某章 T4 红 → 只定向重排该章，不重切。
- 重排后 `--assemble` 重新合卷、跑整卷机检。
- 缺章（`chunks/NN/排版.pdf` 不存在）→ 红并列出缺失章。

### 合并 PDF 探针结论

- 实测 `pypdfium2`（本机版本 API 签名：`import_pages(self, pdf, pages=None, index=None)`）支持合并。
- 用法：`merged.import_pages(src, pages=list(range(len(src))), index=len(merged))`。
- `assemble` 合并后用 `pypdfium2` 重新打开断言页数 = 各章页数之和；不可用则报错，不许静默降级。

## 七、正反示例（弱模型参考，按需读取）

> 3 组弱模型易错场景的对比示例。每组包含：场景描述、错误做法、正确做法、为什么错（一句话）。

### 示例 1：代码混排

**场景**：技术文档里混着代码块和正文说明。

**错误做法**：代码与正文同字体同颜色混在一起，读者分不清哪是说明哪是代码。

```html
<!-- 错误：代码用正文楷体 -->
<p>使用 fetchData() 方法获取数据，然后调用 render() 渲染页面。</p>
```

**正确做法**：代码块用等宽字体（Consolas）+ 浅色底纹，行内代码用等宽字体，与正文楷体明确区分。

```html
<!-- 正确：代码块等宽+底纹，行内代码等宽 -->
<div class="code-block">fetchData()
  .then(data => render(data))
  .catch(err => console.error(err));</div>
<p>使用 <code>fetchData()</code> 方法获取数据，然后调用 <code>render()</code> 渲染页面。</p>
```

**为什么错**：代码与正文视觉混淆，读者需要额外认知负荷去分辨「这是要执行的代码还是描述性的文字」。

### 示例 2：公式排版

**场景**：数学/物理文档里含公式。

**错误做法**：公式当纯文本切行，上下标丢失、分数线消失、求和号变成普通字符。

```html
<!-- 错误：公式当纯文本 -->
<p>根据公式 E = mc^2，能量与质量成正比。</p>
<p>求和公式：sum(i=1 to n) x_i = x_1 + x_2 + ... + x_n</p>
```

**正确做法**：公式用 KaTeX 渲染为专业排版，上下标、分数线、求和号完整保留。

```html
<!-- 正确：KaTeX 渲染 -->
<p>根据公式 <span class="katex">E = mc^2</span>，能量与质量成正比。</p>
<p>求和公式：<span class="katex">\sum_{i=1}^{n} x_i = x_1 + x_2 + \cdots + x_n</span></p>
```

**为什么错**：公式的上下标和符号结构是语义的一部分，丢失后公式含义改变或不可读。

### 示例 3：图文耦合

**场景**：视频讲解稿 + 课件截图，文字内容与图片强相关。

**错误做法**：图与文字挤在同一页，图被压缩到看不清，文字被挤到下一页。

```html
<!-- 错误：图与文字混排，图被压缩 -->
<div class="page">
  <p>如图所示，系统架构分为三层……</p>
  <img src="images/img_001.png" style="width:80mm">  <!-- 被压缩 -->
  <p>第一层是前端层……</p>
</div>
```

**正确做法**：大图（宽 ≥80mm 或高 ≥60mm）独占一页，文字紧随其后另起一页。

```html
<!-- 正确：图独占页，文字另起一页 -->
<div class="page" data-figpage>
  <figure><img src="images/img_001.png" style="width:160mm"></figure>
</div>
<div class="page">
  <p>如图所示，系统架构分为三层……</p>
  <p>第一层是前端层……</p>
</div>
```

**为什么错**：图文耦合的内容，图是理解文字的前提；图被压缩到看不清时，文字描述再好也没用。

## 八、责权审计（现有 L1-L7 的错位）

> 新增 L4 内容类型识别的原因：现有责权存在 3 处错位，都是因为「没有先识别内容类型就动手排」。

### 错位 1：L5 定语义块与代码冲突

**问题**：代码的语义块是语法结构（函数/类/循环），不是散文的主谓宾。现状把代码当散文切语义块，会切坏。

**例子**：
```python
# 散文语义块切法（错误）：在主谓之间切
def fetchData(url):  # ← 如果在 def 和 fetchData 之间切，函数定义被腰斩

# 代码语义块切法（正确）：按语法结构切
def fetchData(url):  # ← 函数签名是完整语义块，不可拆
    return requests.get(url)
```

**解法**：L4 内容类型识别先把代码块标出来，代码块不走 L5 散文语义块逻辑。

### 错位 2：L4 定标注与代码冲突

**问题**：代码里的 `<>` `{}` 是泛型和对象字面量，不是标注符号。现状靠「不上色」规避，但标注密度 ≤3 的规则仍会误伤代码段。

**例子**：
```typescript
// 代码里的 <> 和 {} 是语法，不是标注
function identity<T>(arg: T): T { return arg; }
const obj = { name: "test", value: 42 };
```

**解法**：L4 内容类型识别先把代码块标出来，代码块不走标注密度检查。

### 错位 3：C3 切行禁则对代码不适用

**问题**：「收标点不落行首、开括号不落行尾」是中文排版禁则，但代码的标点就是语法，不能动。

**例子**：
```python
# 如果按中文禁则，开括号 ( 不落行尾
result = someFunction(  # ← 这个 ( 不能挪到下一行
    arg1, arg2
)
```

**解法**：L4 内容类型识别先把代码块标出来，代码块不走中文禁则。

## 九、内容类型识别（L4）

> 在排骨架之前，先识别内容类型，不同类型走不同排版通道。

### 分类标准

| 类型 | 判据 | 排版通道 |
|---|---|---|
| **散文** | 普通段落文字，无代码/公式/表格特征 | 语义完整行 + 标注聚焦 + 语义分块 |
| **代码块** | 三反引号围栏、或缩进 ≥4 空格、或代码特征字符密集（`= ; { } ( )` 等） | 等宽字体 + 底纹 + 宽度优先切行 |
| **公式** | `$...$` / `$$...$$` 包裹，或含数学符号模式（`\sum \int \frac \sqrt` 等） | KaTeX 渲染 |
| **参数表** | 连续 `|` 行（md 表格）或键值对列表 | 表格排版（table-layout:fixed） |
| **图文耦合** | 图片 + 紧邻的文字描述 | 大图独占页 + 文字另起一页 |

### 判定优先级

```
代码块 > 公式 > 参数表 > 图文耦合 > 散文
```

优先级高的先匹配，匹配到就不再往下判。例如一段被三反引号包裹的内容，即使里面含 `$` 符号，也按代码块处理。

## 十、公式处理（L8）

> 识别数学公式/符号，标记为 KaTeX 渲染对象。

### 识别模式

| 模式 | 示例 | 处理 |
|---|---|---|
| 行内公式 | `$E = mc^2$` | `<span class="katex">E = mc^2</span>` |
| 块级公式 | `$$\sum_{i=1}^{n} x_i$$` | `<div class="katex-block">\sum_{i=1}^{n} x_i</div>` |
| 常见符号 | `α β γ π Σ ∫ √ ∞` | 直接保留 Unicode，不转 LaTeX |
| 上下标 | `x^2` `x_i` | 转 LaTeX：`x^{2}` `x_{i}` |

### KaTeX 集成

- **本地资产**：`assets/katex/` 目录（CSS + JS + 字体），渲染时引用本地文件
- **CDN fallback**：本地缺失时引用 `https://cdn.jsdelivr.net/npm/katex@0.16.9/dist/`
- **降级**：CDN 也不可达时，公式用等宽纯文本展示，标注〔公式未渲染〕

## 十一、语义完整行（铁律 6 详细规则）

> 仅对散文生效。切行时优先在语义边界断行，宁可当前行后半留空也不腰斩语义块。

### 切行规则

1. **语义边界优先级**（从高到低）：
   - 句读（。！？；）
   - 语义块末尾（主谓宾完整、标注块完整）
   - 逗号、顿号
   - 词边界

2. **切行逻辑**：
   - 当前行剩余宽度能放下下一个完整语义块 → 继续填充
   - 放不下 → 该块整体挪到下一行，当前行后半留空
   - 行宽上限仍是 36 汉字当量 / 37.8em，但不再「填满才断」

3. **不适用场景**：
   - 代码块：按语法结构切行，不受语义完整行约束
   - 公式：KaTeX 渲染后整体作为一个原子，不可拆
   - 表格：按单元格切行，不受语义完整行约束

### 示例

```
<!-- 错误：宽度优先，腰斩语义块 -->
人 <有目的>地 改造 <自然对
象>，创造使用价值。

<!-- 正确：语义边界优先，标注块完整 -->
人 <有目的>地 改造
<自然对象>，创造使用价值。
```

## 十二、落版纪律（T3 详细规则）

> 从 SKILL.md 移入，按需读取。

- 页高靠浏览器实测 `data-mm`，不靠估算；T3⇄T5 闭环以真品墨点收紧（≤4 轮）。
- 每页一个 `.page`（高 200mm）；`.writezone` 必须为空；断页只写 `break-after: page`；`.page` 不加 `overflow:hidden`。
- 每行一个 `<span class="line">`；标注原子不跨行；切完过禁则 `_glue()`（仅散文）。
- 行宽双闸：≤36 汉字当量（East Asian Width 判，W/F/A=1 其余 0.5）且 ≤37.8em 物理宽（含间隙与行内代码 padding）。
- 正文尖括号必须转义；md 模式不做半角→全角归一；剥强调符只在代码段外、`_` 按「词内不成强调」判。
- 表格 `table-layout:fixed` + 显式 `<col>` 宽（14~46 分）；代码块 `pre-wrap + overflow-wrap:anywhere`。
- 图块：宽 ≥80mm 或高 ≥60mm 的图独占一页（自动判定，不再依赖 `--fig-fullpage`）；小图仍混排（宽 ≤160mm，高按页容量推导，只缩不拆）；题注并进同一块。
- 原文符号上色只给「」与（）；<> 与 {} 不上色（代码语境是泛型与对象字面量）。
- 公式块用 `<span class="katex">` 或 `<div class="katex-block">` 包裹，KaTeX 渲染。
