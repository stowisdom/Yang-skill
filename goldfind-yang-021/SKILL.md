# 黄金样例深拆：一个入口，双门槛筛，三层拆到可迁移

> **意图对齐（按需追问）→ 样例搜集（双门槛筛）→ 深拆 2-3（三层框架）→ 样例包（三件套交付）。**
> 黄金样例 =「已经被成功验证的事物」：拆解、分析、还原，弄清它为什么能成功、怎么做到的，把这套逻辑运用到当前项目。不堆榜单；归因显式；每条可回溯。

## 触发

- 硬触发：`golden:` 前缀（如 `golden: 顶级 SaaS 落地页设计，当前项目：XX 产品官网改版`）；亦可以技能名 `goldfind-yang-021` 调用。
- 不触发：自然语言暗示一律不触发。
- 首次载入本 skill 时，读取同目录 `tone.md` 并按其语气输出；同会话不重复读。

## 入口路由（触发后先判断，不猜）

**意图类型**（决定拆多深）：
- 拆解迁移：领域/事物 + 当前项目 → 三层全给（含「怎么用」）。
- 纯拆解学习：只有领域/事物，没带项目 → 止于前两层（为什么成功+怎么做到）。
- 都不是（找书找课、系统架构选型、评估用户自己的代码库）→ 一句话明说不接 + 给去处（学习资源→find-yang-017；工程架构对标→archfind-yang-020；代码库评估→超边界），不硬接。

**上下文完备度**（决定追问还是直接跑）：
- 给了场景/阶段/受众 → 直接跑。
- 关键上下文全没给 → 只追问一句，不盘问。
- 部分缺 → 自己假设并在样例包里标注「基于假设 X」，用户可纠正后重跑。

**控制方式**：AI 自主推进；用户任何自然语言（「换 XX 拆」「带上我的项目重跑」「只要第一层」）识别意图路由，不用记命令。

## 选品基准：双门槛 + 双象限（核心）

### 第一门槛：成功已验证（结果轴，必须先过）

1. **硬结果佐证**：收入/用户/融资/获奖/定义品类/被广泛模仿——要数字或事实，不收「据说好」。
2. **经得起时间**：存活且持续被引用；或**正在定义标准**（前沿也算）。
3. **业内公认**：被顶级玩家研究、模仿。

### 第二门槛：可还原（材料轴）

1. **原创建者一手**：自述/访谈/复盘/原始实物——最硬。
2. **专业深度二手**：逐页/逐层拆解的专业 teardown——可用，但必须标注「二手还原」。
3. **营销软文、成功学、鸡汤拆解——一律不进。**

### 双象限（过了门槛，报告里分开标）

- **经典**：完整验证 + 行业原点（Rams 十原则、Airbnb 原始 deck 这条线）。
- **前沿**：正在定义标准的新范式（新交互形态、新文档形态）。

两象限都找不到够格的 → 直说「这个领域目前只有平庸区样本」，不拿平庸货凑数。

## 深拆框架：三层（核心）

1. **为什么能成功**：用领域审美/思考尺子逐条判（UI→Rams 十原则式；BP→一页一论点式；商业模式→飞轮/单位经济；PRD→叙事纪律）+ 情境归因（时代/资源/时机贡献了多少）。
2. **怎么做到的**：逆向还原——结构（由哪些部件构成）/ 路径（先做什么后做什么）/ 决策点（关键取舍）。
3. **怎么用到当前项目**（带项目才有）：迁移要点 + 失效边界（什么条件下这套逻辑不管用）+ 落地第一步。

各层操作化问题清单见 REFERENCE.md「三层框架」。

## 归因纪律（本 skill 特有，硬约束）

- 每个样例必标「**可归因逻辑 vs 情境运气**」——把方法论和运气分开，防止照搬翻车。
- 迁移要点必带失效边界；没有免费午餐。
- 不神化样例：成功者的自述也要过筛（自我美化是常态），多源互证优先。

## 产出：样例包（只在 chat，不落盘）

1. **结论先行**：2-3 个黄金样例一句话定位 + 象限标注（经典/前沿+一句话理由）。
2. **每样例三件套**：实物链接 + 验证数字 + 还原材料出处。
3. **三层深拆**：为什么能成功 / 怎么做到的 / 怎么用（带项目才有第三层）。
4. **未收录说明**：没进深拆的候选一句话交代为什么；不够格的直说。
5. **出处清单**：每条带 URL，二手还原标层级。

完整模板见 REFERENCE.md「样例包模板」。

## 边界

- 不做学习资源清单——找书找资料走 find-yang-017。
- 不做技术系统架构对标/选型——走 archfind-yang-020。
- 不做用户自己代码库的评估——本 skill 只拆外部成功事物。
- 不替用户落地执行——迁移要点给到，做到项目里是用户的事。
- 不伪造出处；二手还原必标层级，不冒充一手。
- 样例包不落盘。
