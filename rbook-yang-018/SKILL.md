# rbook-yang-018 长文转小册子 PDF

## 定位

把一篇信息密度高、没时间通读的硬长文——经典书、论文、综述、深度文章都算——变成一份**一天能消化、零基础成年人也能看懂**的中文小册子 PDF。
核心不是「摘要」，是「知识框架」：认知图式拆解 + 高 VOI 反常识 + 全书思维模型全覆盖。
**最终语言一律中文**：无论输入是什么语言（中/英/其他），小册子全部翻译为中文；术语、人名、书名一律中文呈现（专有名词首次出现可附原文，如「损失厌恶（Loss Aversion）」）。

## P1 触发

- **触发词**：`/rbook {输入}`（斜杠命令，硬前缀）
- **输入**：PDF / MD / Word / EPUB / URL / 粘贴文本，可能是一整本书或一篇长论文
- **触发条件**：
  - 启动：消息以 `/rbook` 开头且带输入（文件路径 / 链接 / 粘贴文本）
  - 启动：`/rbook` 后没带输入 → 先问「把材料给我（文件/链接/粘贴）」，不猜
  - 启动：用户已把材料交给 AI，明确说「做成小册子」
  - 不启动：只出现「读书笔记」「知识框架」等泛词、无小册子意图

## 路由段

**入口路由**（/rbook 触发后）：

- `/rbook {输入}` → 开始处理 → 进主流程
- `/rbook`（空）→ 问输入来源
- 处理中用户的自然语言控制（「改」「停」「继续」「换本书」）→ AI 识别意图路由

**接力路由**（find-yang-017 → rbook 是固定管线）：find-yang-017 产出材料清单后，用户点名其中一条 → 该材料直接进主流程（等同 `/rbook {输入}`），不重问来源。

**主流程路由**（七段顺序走）：

```
1 输入解析 → 2 全书扫描 → 3 认知图式拆解 → 4 小册子生成 → 5 排版 → 6 PDF 产出 → 7 验收
```

**工具路由**：

- 输入解析 / 全书扫描：读文件、分块读入（脚本辅助提取文本）
- 内容生成：AI 产出 Markdown
- PDF 产出：`scripts/md2pdf.py`（Markdown → HTML/CSS → Chromium 系浏览器 headless 打印 PDF）

**用户的控制方式**：不用记命令。AI 自主推进；用户的任何自然语言输入由 AI 识别意图路由。

## P2 主流程七段

### 1 输入解析

- 识别输入格式（PDF / MD / Word / EPUB / URL / 文本），提取可读内容与目录结构。
- 格式读不了 → 明确告诉用户缺什么工具，不硬来。
- **中间产物规约**：提取/OCR/下载的中间文件统一放 `{工作目录}/_rbook-tmp/{材料名}/`，PDF 交付验收后整目录删除——不留散落的临时文件。

### 2 全书扫描（★ 防漏图式关卡）

目标：**穷尽全书核心图式/思维模型**，这是用户的硬要求——错失一个可能「开悟」的点就是失败。

- 2a 先读目录 / 前言 / 各章标题 → 预判全书骨架。
- 2a* **论文/综述骨架路由**：论文和综述类输入，优先沿原文自身章节结构逐层放大（Alammar 式：从原文架构图出发拆解）；确有更优重组才重组，且在小册子里标注「此处重组了原文结构」。书/文集类维持自由重组。
- 2b **分块读入**正文（每块控制在上下文能消化的体量，省 token）：每块只做一件事——挖出新图式/思维模型，并入「全书图式穷尽清单」。
- 2c **穷尽检查**：把清单对照全书结构逐章查漏——哪一章还没有图式进清单？哪个概念只出现一半？查漏补缺后再往下走。

**省 token 原则**：不一次性塞全书；先粗后细（骨架先行，再精读关键块）；图式清单先行，逐块并入。

### 3 认知图式拆解

- 按认知负荷理论，把图式清单排序：**基础图式 → 高阶图式**（先垫地基，再盖楼）。
- 每个较高难度的认知图式，标出「**所需前置知识**」——缺失的前置知识要补出来。
- 产出：图式清单（编号、难度、前置依赖）。
- **具体提炼规则见 P3 提炼标准**——材料过手只出三类产物（图式 / 骨架 / 建模），各守判别线。

### 4 小册子生成

- **卡片式组织**（图式主体卡 = 五格骨架；三类产物进卡方式，规则见 P3）：
  1. **一句话结论**：卡片核心主张，加粗。
  2. **硬数据 / 机制**：DIKW 过滤后的证据（见 P3.5）；结构化可视化至少一处（对比表格 / 编号流程，md2pdf v2 均支持）。
  3. **微例子**（图式主体卡必带）：一个真实例子走一遍。原文有现成例子的用原文；原文没有则允许编者按机制**示意重构**，必须标注「（示意重构）」。
  4. **元启示**（回到知识本身的九问，见 P3.6）。
  - 骨架卡 / 反常识卡 / 收尾卡：五格灵活裁剪，不硬套全五格；微例子和可视化为可选项，提炼不出明说「这格没有」。
  - 骨架 → 卡片的前置预热区（按依赖顺序拆到「小学生能懂」）
  - 建模 → 卡片内要点（名称 + 一句本质 + 应用场景 + 四环）
- **全文中文**：输入是什么语言不重要，最终输出一律中文（书名、术语、人名也中文呈现，专有名词可首次附原文）。
- **高 VOI 筛选**：只保留高信息价值内容；平淡的过渡句、背景废话一律砍。
- **反常识检查**：全书最反直觉、最有冲击力的点，必须单独拎出来、写足（这是「开悟」机会所在）。
- 全文中文；7000-10000 字为参考值，允许按内容浮动，但保持「别太长、一天能读完」的感觉。

### 5 排版（用户明确要求，与正文同等重要）

- **A.a 层次编号**：知识层次用希腊大写字母＞小写字母＞数字；组合形式「大写字母--小写字母」，数字独立。示例：`Α 章 / Α--α 节 / 数字 1`（罗马数字用于比希腊大写更高一层）。
- **A.b 卡片布局**：`---` 单独一行 = 卡片分隔，一张卡片 = 一个认知图式 + 前置知识预热；组块对比可用 `|` 简单表格（首行表头，渲染器已支持）；代码块用 ``` 围栏。排版能力边界以 `scripts/md2pdf.py` 文档字符串为准。
- **A.c 高 VOI 筛选**：内容上只保留高价值，见第 4 段。
- **A.d 视觉排版 = 正文文字质量同等高度**：标题层级、卡片边框、留白、字体都要讲究，不能只是文字堆叠。

### 6 PDF 产出

- 调 `scripts/md2pdf.py` 把 Markdown 转成 PDF 文件（HTML/CSS 排版 → Chromium 系浏览器 headless 打印）；支持段落/列表/引用/粗斜体/行内代码/表格/代码块。
- **环境要求**：脚本在 Windows / macOS / Linux 上自动查找 Edge / Chrome / Chromium；三个都找不到时报错，可用环境变量 `MD2PDF_BROWSER` 指向浏览器可执行文件手动指定。
- 产出文件命名：`{书名}-小册子.pdf`，放在用户指定的输出目录（默认当前工作目录）。

### 7 验收

- 把 PDF 路径给用户，请用户打开检查：内容（高 VOI / 反常识 / 全覆盖）、排版（卡片 / 编号 / 美观）。
- 用户说「改」→ 靶向修（只修跑偏部分，已确认内容不动）→ 重新生成。
- 用户确认 → 完成。

## P3 提炼标准（材料过手，只出三类产物，各守一条判别线）

### 3.1 「图式」＝ 认知图式（组块）

- **判别线**：大脑一次只能挂住 3-4 个图式。例：电话号码 123456789 是 9 个图式；拆成 123/456/789 就是 3 个，认知难度就降下来了。
- **产出要求**：**材料中的每一个知识点**都拆成 3-4 个组块；每组块一张卡；卡内要点超过 3-4 个就再分组块，不许超载。

### 3.2 「骨架」＝ 前置必备知识

- **判别线**：没有它，用户根本读不动这段材料。
- **产出要求**：按「懂A才能懂B」的依赖顺序排列；A 若还有更浅的依赖，继续拆，直到「小学生能懂」为止。

### 3.3 「建模」＝ 思维模型（抽象完成规律化）

- **判别线**：把这段材料的方法/原理压缩成可迁移工具，换个情境仍然成立。
- **完成建模的标准链**（四环齐全才算建模完成，缺环就标出缺哪环）：前提假设 → 推理逻辑 → 原理定义 → 反向参考定义。
- **产出要求**：名称 + 一句本质 + 应用场景；四环写进卡内要点。

### 3.4 不硬凑

- 提炼不出就明说「这段没有」，不硬凑。

### 3.5 DIKW 过滤（信息阶梯底线）

- 输出至少到「信息」层——数据必须经过解读才能进入小册子。
- **数据层（原始数字）**：只在它直接支撑一张卡的**唯一核心主张**时保留，且紧跟一句人话解读（如「0.70σ——教育研究里 0.8 为大，已接近大效果门槛」）。
- **信息层**：多个数据点合并成行为级解读（如「读教材 ≈ 不读」替代 .586 vs .632）。
- **判例**：一张卡只留 0-1 个锚点数据；其余原始数字全部换成人话。没有锚点价值的纯数据不进输出。

### 3.6 元启示格（九问规格）

图式主体卡和建模卡必须包含元启示格——回到知识本身答以下问题：

**陈述性知识（五问）**：
1. 解决了什么问题
2. 怎么解决的
3. 解决了什么冲突
4. 完成什么任务
5. 满足了什么需求，之前没有它时怎样

**流程知识（再加四问）**：
6. 怎么定位问题
7. 怎么算错
8. 有哪些验收节点
9. 怎样进行路由选择

纯思辨/文学材料（如加缪）答不上流程四问 → 退回自然形态的五问，不硬压。

## P4 质量关卡（五条硬线，缺一不交）

1. **反常识**：小册子必须包含全书最反直觉的 3-5 个点，单独成卡，写足写透。
2. **VOI 双过滤**：每一段过两问——「有没有信息增量」且「能不能改变用户的决策/实现/设计」；两问都不过就删。解释力优先，不凑条数。
3. **DIKW 底线**：输出至少到信息层；原始数据只在支撑核心主张时保留，其余换成人话（见 P3.5）。
4. **穷尽**：全书图式穷尽清单完整，无整章遗漏；不确定的图式宁可多列，不可漏。
5. **认知负荷**：每张卡新术语 ≤1 个，首次出现当场白话定义（不依赖读者记得前面章节）；机制讲不清时降级为「照着做的步骤」（仅限真有操作动作的材料，纯思辨不硬压）。

## P5 边界

- 不逐字翻译原文，不做流水账摘要。
- 不擅自扩大篇幅（「别太长」是硬感觉）。
- 不编造原文没有的核心图式——清单要能对应回原文位置。
- 不丢前置知识：高难度图式缺前置预热就是不合格。
- 不硬凑：提炼不出就明说「这段没有」。
