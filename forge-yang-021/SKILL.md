# Skill: forge-yang-021 · 干中造——任务流中的 prompt 快速锻造

## 第一性原理

好 prompt 不是写出来的，是**组织**出来的。组织有三个自由度：

- **形**（几何排布）：点开空间、线定方向、面围边界、环闭反馈——管怎么排布。
- **料**（调用模型）：架构设计、思维模型、流程知识、验收节点、黄金样例（开放分类，包含但不限于）——管放什么。
- **路径**（上下文供给）：文件路径即轻量标识符，运行时动态加载——管喂什么上下文。

**产出契约**：成品 =「调用模型块」+「上下文路径块」，末尾附一句维度自检。
**干中造，干中用**：分钟级、当场贴回、不落盘、不接管任务本身。

## 触发（硬匹配）

- 用户的消息以「干中造」开头（冒号可选）才触发，后接一句意图。
- 意图为空：只反问「要锻什么」，不猜。
- 自然语言聊到 prompt / 锻造，一律不触发。
- 三段门控的重创作不归这里——那是 prompt-yang-014 的活。

## 步骤路由（五步，≤3 轮对话预算；AI 侧动作不耗轮次）

1. **收意图**：触发轮完成。意图太糊 → 一问澄清再走。
2. **摸项目**：AI 自主摸当前项目，产出「路径候选清单」——规程读 REFERENCE「摸项目规程」。摸不到相关文件 → 路径块声明空缺，不硬凑。
3. **逐维快问**：一轮 AskUserQuestion 打包问三件事——**形**（点/线/面/环）、**料**（五料多选）、**路径**（候选清单勾选）。最多两轮。选型语言见 REFERENCE「几何四形」「调用模型五料」。
4. **组装出稿**：按「形 × 料 + 路径」从 REFERENCE「模式卡」取骨架组装；标签规范见 REFERENCE「XML 标签法」。
5. **交付即用**：成品当场贴出 + 维度自检一句；用户点名改哪就改哪，不整稿重写。

**捷径**：用户说「直出」→ 跳过第 3 步，全按默认〔假设〕直接出稿，事后点改。

## 工具路由

- 摸项目：Glob / Grep / Read（内置）
- 快问：AskUserQuestion
- 出稿：对话文本直接输出——**不写任何文件**

## 边界

- **不落盘**：不写进度、不存档，对话即全部状态。
- **不接管任务**：只管「把 prompt 组织出来」这一件事。
- **最小高信号**：上下文路径宁少勿滥——每条路径必须答得上「为什么带它」。
- 一次只锻一个 prompt；要锻第二个，重新触发。
